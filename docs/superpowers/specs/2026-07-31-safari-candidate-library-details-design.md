# 目标

将 Safari 用户主动采集的公开媒体候选保留为可浏览的候选库：可按类型/推荐性筛选、重新读取 Safari 最近一次采集快照、查看每项已知详情和安全诊断摘要。只有在用户明确选择并导入某一候选后，才沿用现有 `analyzeMedia()` 对该单项进行正常探测，并在下载界面展示探测到的完整格式资料。

# 范围

## 候选数据与兼容

1. 将 `MediaCandidate` 存储 schema 从 `v1` 升级为兼容读取旧记录的新版本；旧记录仍可被读取，新增字段缺失时显示“未知”。
2. Safari 导入时为每项候选保存以下已经由用户脚本采集或可从 URL 安全推断的非敏感信息：
   - `captureSource`：DOM、preload、metadata 或 performance；
   - `qualityHint`：现有 HLS/DASH 推荐性及 URL 中可解析的固定分辨率；
   - `containerHint`：HLS、DASH 或 URL 后缀推断的容器；
   - `pageTitle`、`pageURL`、采集时间、候选类型。
3. 每次 Safari 导入保存同一份页面诊断摘要到候选库：候选数、资源数、媒体类资源数、iframe 数、域名数和 initiator 计数。摘要不存完整资源列表、Cookie、Authorization、请求头、签名 URL 查询值、DRM/license 数据。
4. 继续维持 50 条上限、URL 去重、按最近使用/导入排序和 24 小时 TTL；清空候选库同时删除对应诊断摘要。

## 候选库界面

1. 下载页“最近候选”改为候选库入口，默认显示最近候选。
2. 提供本地筛选：全部、推荐、HLS、DASH、视频、音频、页面；不触发网络请求。
3. 每条候选显示：来源标签、媒体类型、质量提示、容器提示、页面标题/域名、相对采集时间。
4. 点按候选先打开本地详情，再由“导入并分析”进入现有确认和 `analyzeMedia()` 流程；不在打开详情时访问候选 URL。
5. 详情页显示：
   - 已采集/可推断：类型、来源、推荐性、容器、固定分辨率（若可解析）、页面标题与采集时间；
   - 需要探测：清晰度、视频编码、音轨/语言、码率、精确预估大小、HLS/DASH 变体数；未探测时逐项显示“未知，导入并分析后可获取”。
6. 候选库顶部提供“读取 Safari 最新采集”：只读取 Safari 用户脚本上一次通过菜单或浮动按钮主动写入的 GM 快照，将其合并入本地候选库；不刷新 Safari 页面、不调用媒体 URL、不修改 Safari 的 GM 存储。
7. 无候选或 Safari 快照为空时，显示现有诊断摘要与可操作说明：在 Safari 页面运行“导入本页媒体候选到 Yoinks”；诊断不暴露资源 URL 或敏感请求信息。

## 已导入候选的媒体资料

1. 用户确认“导入并分析”后保留现有策略：视频/音频候选优先正常探测来源页面，失败后回退至已采集直链；HLS/DASH 直接按候选处理。
2. 分析成功后，格式选择界面继续以 `MediaProbe` 的真实格式数据展示清晰度、编码、音轨、容器和预估大小；HLS/DASH 的变体仅以该次正常探测返回的数据为准。
3. 分析失败保留既有错误流程；候选库条目、详情和诊断仍可再次查看或重新导入。

# 信息架构决定

用户已选择统一候选库：现有“最近候选”保留为唯一入口，继续容纳 Safari、发现和手动候选。Safari 条目展示采集来源、质量/容器提示和诊断；发现/手动条目保留原有功能，Safari 专属字段显示“不适用”。

# 数据流

```text
Safari 用户手动采集
  → GM 快照（候选 + 非敏感诊断摘要）
  → Yoinks「读取 Safari 最新采集」
  → sanitize + 合并到本地候选库（50 条/24 小时）
  → 筛选列表 → 本地详情
  → 用户确认导入
  → 仅该候选运行现有 analyzeMedia()
  → 格式界面显示真实媒体资料
```

# 隐私与安全边界

- 不增加全局网络监听、后台资源遍历、额外 HEAD/Range 请求或自动批量探测。
- 不读取、保存、导出或展示 Cookie、Authorization、User-Agent、请求头、DRM/license 或完整 Performance Resource 清单。
- 签名媒体 URL 的 query 仅为现有下载链所需而保留在本地候选 URL；UI 摘要、诊断和日志使用脱敏 URL。
- 刷新只表示重新读取用户主动采集的 Safari 快照，不等同于刷新网页或重新抓取媒体。

# 非目标

- 不自动解析或下载候选库内全部项目。
- 不实现 Cat-Catch 式全局网络捕获、Cookie 收集或跨站会话复用。
- 不承诺在未探测前显示实际音轨语言、编码、精确大小或自适应变体明细。
- 不改变 Safari 用户脚本的候选识别范围与优先级，除非为传递既有来源字段所必需。

# 验证与验收

## 自动验证

1. 扩展 `verify_media_candidates.ts`：旧记录兼容、扩展字段清洗、TTL、去重、上限、清空诊断。
2. 扩展 `verify_safari_media_candidates.ts`：候选来源、质量/容器提示和诊断摘要只保留白名单字段；序列化结果不含敏感键。
3. 新增候选库筛选/详情纯函数验证：筛选结果、未知字段文案、刷新仅合并快照且不改变 Safari 存储。
4. 项目 TypeScript diagnostics 为 0，`scripting-ts project "Yoinks" --check` 通过。

## 真机验收

1. 在 Safari 页面手动采集，Yoinks 读取后候选库显示数量、类型、来源、推荐性和已知容器/清晰度提示。
2. 分别筛选 HLS、DASH、视频、音频和推荐项，结果不触发网页刷新或网络探测。
3. 打开详情时，未知项目明确标注“导入并分析后可获取”。
4. 点击“读取 Safari 最新采集”后，新增快照合并、去重且不清除 Safari 的原快照。
5. 导入单条候选，确认只对这一条触发分析；成功后格式资料与现有下载流程一致。
6. Safari 没有快照/没有候选时，看到安全诊断与操作提示，不显示完整资源 URL 或凭据。

# 风险

Safari GM 快照在应用与扩展间同步可能延迟；界面必须明确显示最后采集时间和“读取 Safari 最新采集”结果，不将旧快照误称为实时页面状态。精确媒体属性受站点和解析器影响，必须只展示实际探测结果，未知时不猜测。
