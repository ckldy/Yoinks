# Safari 候选与唯一视频格式自动载入

**日期：** 2026-07-31  
**状态：** 待用户审阅后实施  
**范围：** Yoinks 的 Safari 候选导入与单链接分析完成后的格式初始选择。

## 目标

减少无意义的确认步骤，同时保持多格式选择权：

1. Safari 候选只有一条时，直接导入并自动分析；有多条时才显示候选选择菜单。
2. Safari 候选被选中后立即开始分析，不再显示“导入并分析媒体链接”的二次确认。
3. 任意单链接分析完成后，若结果中恰有一条视频候选，自动将其载入为当前格式；只有多条视频候选时，用户才需要在“选择格式”菜单中决定。

不触发自动下载；“自动载入”仅表示设置 `selectedChoice`，保留用户点击下载的现有控制权。

## 统一规则

在 `index.tsx` 新增一个纯逻辑的“分析结果初始格式”决策点，供所有 `analyzeMedia()` 成功路径共享：

- 收集 `probeResult.choices` 中 `kind === "video"` 的候选。
- 视频候选数为 1：返回该视频候选，作为默认已载入格式。
- 视频候选数为 0 或大于 1：不自动选中，保留现有手动格式选择。
- 已有自动下载路径保持优先：当启动剪贴板自动下载被请求且开关开启时，继续使用 `resolveAutomaticChoice()`，并由该策略决定下载格式。
- 抖音唯一候选的旧特例被该通用规则覆盖：唯一视频自动载入；纯音频或多个视频不因为平台而绕过统一规则。

音频候选不计入“唯一视频”数量。因而“1 条视频 + N 条音频”会自动载入视频；用户仍可手动打开格式菜单改选音频。纯音频探测结果保持手动选择，避免把“唯一视频”规则扩展为未请求的音频自动选择。

## Safari 导入流程

`importSafariMediaCandidate()` 读取并记录候选库后：

- 候选数为 1：直接调用 `analyzeSafariCandidate(envelope.candidates[0])`。
- 候选数大于 1：显示现有候选 Action Sheet；用户选择后直接调用 `analyzeSafariCandidate(candidate)`。
- 取消菜单、无候选、读取失败，以及 `analyzing` / `downloading` / 批量队列运行中的保护行为不变。

`analyzeSafariCandidate()` 现有的来源页优先探测、直链回退、Safari Referer、标题对齐、候选库记录、脱敏日志和清除 GM 槽位的逻辑均不变。

## 影响与非目标

- 影响范围为所有复用 `analyzeMedia()` 的单链接入口，包括手动输入、剪贴板、历史链接、Safari 候选和相关候选库入口。
- 不修改候选排序、格式生成、下载器、自动下载策略、播放列表批量格式选择、Cookie/授权边界或 Safari GM 数据结构。
- 不新增持久化偏好，不自动开始下载。

## 验证

新增或扩展纯逻辑验证，覆盖：

1. 唯一视频（含多音频）自动选中该视频。
2. 多视频不自动选中。
3. 纯音频不自动选中。
4. Safari 一条候选直接分派分析；多条候选必须由用户菜单选择（通过提取的纯分派函数或可静态验证的逻辑实现）。
5. 现有 Safari 候选安全验证继续通过。
6. 全项目 TypeScript diagnostics 为零；运行既有 Safari 候选验证和项目启动回归。

## 真机验收

1. Safari 采集仅一个 HLS/MP4 候选，点“从 Safari 导入媒体候选”后应立即进入“正在分析”，没有候选菜单和确认框。
2. Safari 采集多个候选，显示一次候选菜单；点其中一项后立即分析，没有确认框。
3. 一个视频格式加多个音频格式的页面，分析结束后“选择格式”直接显示唯一视频标签，下载按钮可用；菜单仍能改选音频。
4. 多视频格式页面，分析结束后仍显示“选择格式”，必须由用户手动选择。
