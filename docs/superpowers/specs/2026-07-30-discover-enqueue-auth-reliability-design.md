# 目标

修复发现页“加入批量队列”在异常时可能长期保持加载状态的问题；使入队前预解析与既有单链/批量下载的认证策略一致，同时不持久化 Cookie、会话对象或请求凭据。

# 范围

1. `DiscoverTab.addToQueue()` 使用 `try/catch/finally`，保证 `loading` 无论成功、逐项失败或意外异常均会恢复。
2. 发现入队预解析采用无交互认证策略：
   - 小红书：若已有会话，使用已有会话探测；
   - YouTube、抖音：先匿名探测；
   - YouTube 仅当匿名错误明确表示需要新 Cookie/登录时，尝试已有 YouTube 会话重试；
   - 不在发现页自动弹出登录 WebView。
3. 队列条目只记录 `probeAuthorizedPlatform`（平台枚举），以标记缓存的 `MediaProbe` 是否依赖该会话；不得存 Cookie、Cookie 文件路径、token、请求头或 WebView 对象。
4. 批量下载复用缓存 probe 时，若有 `probeAuthorizedPlatform` 则重新取得该平台当前会话；会话不可用时失败并提示重新登录，不静默降级为匿名下载。
5. 最近候选只写入实际新增进队列的发现条目，避免重复项或容量限制导致的错位。

# 非目标

- 不修改发现引擎的 `--flat-playlist` 行为；发现结果仍是 URL/title 列表。
- 不向发现引擎、Safari userscript 或日志添加 Cookie、Authorization、全局网络监听或站点专用解析。
- 不在本次将导入的 cookies.txt 改为平台绑定；该隐私边界改进独立排期。
- 不处理 Javtiful 等站点页面级 yt-dlp 无格式问题。

# 数据流

1. 用户在发现页选择条目并点击加入。
2. UI 设置加载状态，逐项运行无交互预解析策略。
3. 成功项写入队列：URL、标题、MediaProbe、可选 `probeAuthorizedPlatform`。
4. 批量执行时复用 MediaProbe；若该 probe 标记为认证依赖，则重新获取同平台现有会话以创建临时 Cookie 文件。
5. 任意 UI 异常走 catch 显示简洁状态；finally 恢复可操作状态。

# 验收与验证

静态/服务验证：

- 新增或扩展验证覆盖队列平台标记的保存与更新、实际新增项识别。
- TypeScript 项目诊断为 0。
- 运行发现服务与批量队列既有验证。

真机验收：

- 预解析异常后“加入队列”按钮恢复可点；
- 已登录 YouTube 受限条目：匿名失败后可用已有会话预解析、入队、批量复用 probe 并带会话下载；
- 未登录 YouTube 受限条目：不入队、不给出意外登录弹窗；
- 已登录小红书发现条目使用已有会话；
- 重复项在前、实际新增项在后时，最近候选仅记录实际新增项；
- 入队至下载期间会话失效时，任务清晰失败并提示重新登录。

# 风险

会话从入队到批量执行期间可能失效；本设计选择明确失败而非匿名降级，确保探测结果和下载上下文一致。真实 WebView、Cookie 和下载闭环只能在设备上验收。
